# Architecture

## Overview

Round Living is a Nuxt 4 content-driven site using SSR with static generation capability. Content is managed via `@nuxt/content` v3 (SQLite-backed markdown collections). UI is built with Nuxt UI v4 + Tailwind CSS v4.

## Rendering Strategy

- **Default**: SSR — dynamic content fetching on request
- **Optional**: Full static generation via `nuxt generate`
- No hybrid per-route configuration; all routes use the same strategy

## Layers

```
Frontend (Nuxt UI, Vue 3)
    ↓
Routing & Page Layer (file-based, catch-all routes)
    ↓
Composable/Logic Layer (queryCollection, useSeoMeta, useAsyncData)
    ↓
Data Layer (@nuxt/content with SQLite, built at build time)
    ↓
Content Sources (Markdown files in content/)
```

## Routing

| Route | Component | Data Source | Notes |
|---|---|---|---|
| `/` | `pages/index.vue` | — | Static home page |
| `/articles/[...slug]` | `pages/articles/[...slug].vue` | `articles` collection | All articles visible |
| `/info` | `pages/info/index.vue` | `siteInfo` (live only) | Grouped category index |
| `/info/[...slug]` | `pages/info/[...slug].vue` | `siteInfo` (live only) | 404 if draft/review |

Catch-all `[...slug]` routes match unlimited nesting depth. 404 is handled manually when no markdown file matches.

## Content Collections

Defined in `content.config.ts` with Zod schema validation:

**`articles`** — `content/articles/**` → `/articles/`
- No status gating; all files render

**`siteInfo`** — `content/info/**` → `/info/`
- `status: 'draft' | 'review' | 'live'` (default: `'live'`)
- Only `live` pages render; others return 404
- Search also excludes non-live pages

Both collections share optional SEO schema: `image`, `og.{title,description,image}`, `twitter.{card,title,image}`

## Data Flow

### Page render
```
Request /articles/domes/geodesic-domes
  → Nuxt matches [...slug] route
  → useAsyncData() → queryCollection('articles').path(route.path).first()
  → @nuxt/content queries SQLite
  → Returns { title, description, body, toc, og, twitter, image }
  → ContentRenderer renders markdown as HTML
  → Page displays with breadcrumbs + TOC sidebar
```

### Search
```
Layout mounts
  → queryCollectionSearchSections('articles') + queryCollectionSearchSections('siteInfo')
  → Filter siteInfo results to live-only paths
  → User types → match against section content
  → Navigate to selected result
```

## State Management

No Pinia. All state is local to components:

- **Route state**: `useRoute()` drives data queries
- **Async data**: `useAsyncData('articles-' + route.path, ...)` — SSR-compatible, keyed per route
- **UI state**: `ref` — `isSearchOpen`, `searchTerm`
- **Color mode**: `useColorMode()` (Nuxt Color Mode, stored in localStorage)
- **Computed**: breadcrumbs, TOC flattening, info page grouping

## Page/Layout Hierarchy

Single global layout (`default.vue`) wraps all pages:

```
app.vue  →  <UApp> + <NuxtLayout> + <NuxtPage>
  └─ layouts/default.vue  (header, nav, search modal, decorative bg, footer)
      ├─ pages/index.vue
      ├─ pages/articles/[...slug].vue  →  ContentRenderer
      ├─ pages/info/index.vue  →  grouped cards
      └─ pages/info/[...slug].vue  →  ContentRenderer
```

## Key Patterns

### SEO Cascade (all content pages)
```
twitter fields → og fields → base title/description/image
```
Applied via `useSeoMeta()` with `??` fallback chain.

### Status Gating (info only)
Info catch-all throws 404 if `page.status !== 'live'`. Same filter applied to search results in the layout.

### TOC as First-Class Feature
Auto-parsed from markdown headings by `@nuxt/content`. Rendered in a sticky sidebar (desktop only). Fragment anchors generated by `ContentRenderer`.

### Styling Architecture
- Tailwind v4 utilities inline in templates
- Nuxt UI color tokens (`primary: emerald`, `secondary: sky`, `neutral: slate`)
- `.content-docs` on article elements for markdown typography
- `.content-docs-info` additionally suppresses heading anchor decorations on info pages

## Build Characteristics

- `npm run build` → `.output/server/` (SSR entry) + `.output/public/` (static assets)
- `npm run generate` → fully static HTML
- SQLite database compiled from markdown at build time
- No linting, no test runner, no CI/CD configured
